# AI Vault Maintainer

Этот skill применяется только к vault `/Users/yakovlev-alex/Documents/AI`. Он задаёт рабочий порядок для добавления и правки заметок, но не является источником рубрики: актуальные правила всегда читать из `AGENTS.md`, ближайших index-файлов и уже существующих заметок.

## Принцип

Сначала определить место знания в графе, потом писать. Index — карта, leaf — самодостаточный chunk для retrieval, сравнения — отдельный раздел.

## Обязательное чтение

Перед содержательной правкой:

1. Прочитать `AGENTS.md`.
2. Прочитать `AI — база знаний.md` или ближайший section index.
3. Прочитать 1-2 соседние заметки того же типа.
4. Проверить дубликаты через `rg` по заголовку, slug и ключевым wikilinks.

## Выбор действия

| Ситуация | Действие |
| --- | --- |
| Новая самостоятельная тема | Создать leaf в правильном разделе и добавить входящую ссылку из parent/index |
| Дополнение существующей темы | Обновить leaf, не раздувая index |
| Новая подтема внутри длинной заметки | Вынести новый leaf и связать через index/parent |
| Сравнение подходов | Писать в `Сравнения/`, не в тело обычного leaf |
| Harness engineering | Писать в `Harness/`; не тащить сравнения с методологиями в HEG leaf |
| Cloud agent platform | Писать в `Cloud Agents/` с именем `ca-<slug>.md` |

Если раздел неочевиден или правка требует переименования файла, сначала спросить пользователя.

## Запись заметки

- Писать на русском; оставлять английскими только имена, slugs, команды, API-поля, пути, package names и устойчивые термины из `AGENTS.md`.
- Для внешнего ресерча проверять актуальные первоисточники и заполнять `source` во frontmatter.
- Для новой или существенно изменённой заметки обновлять `created`/`updated`, `tags`, `parent`, H1, `## Ключевые инсайты`, тело и `## Навигация`.
- Не копировать длинные фрагменты источников; конспектировать своими словами.
- Не создавать orphan notes: у новой заметки должна быть входящая ссылка из index или parent.

## Проверка и коммит

После правок:

1. Запустить `.githooks/validate-ai-vault.py --all` для широкой проверки или положиться на staged-only hook перед коммитом.
2. Просмотреть `git diff` и убедиться, что в коммит попадут только свои изменения.
3. Сделать Git-коммит. Содержательная правка vault агентом не считается завершённой без коммита.
4. Если коммит невозможен из-за чужих dirty changes или ошибки hook, явно сообщить причину и список файлов своей задачи.

## Частые ошибки

| Ошибка | Исправление |
| --- | --- |
| Research заметка остаётся на английском | Переписать прозу на русский до коммита |
| Index превращается в статью | Оставить навигацию и 1 ключевой инсайт; детали вынести в leaf |
| В HEG leaf появляются Superpowers/CE сравнения | Перенести сравнение в `Сравнения/` или обзорный index |
| Новая заметка не связана | Добавить строку в parent/index и блок `## Навигация` |
| Validator падает | Исправить staged Markdown или убрать файл из индекса |
